# Dependency security review

Reviewed 27 September 2026 against `pnpm audit --prod --json` and the installed dependency sources. The initial audit reported **10 findings: 5 high, 5 moderate, no critical**. These are package findings, not ten demonstrated vulnerabilities in Kite. This is a bounded static reachability review, not an exploitation test or a clean security audit. **The findings below remain unresolved in the dependency graph.** Re-run the production audit after dependency changes; do not treat this snapshot as a replacement for CI auditing.

The unused web `@coral-xyz/anchor` dependency was removed. The final workspace-wide production audit still reports **10 findings (5 high, 5 moderate)** because the separate Anchor tooling workspace also depends on `toml` through `@anchor-lang/core`. That parser is no longer a web dependency. Its two `toml` advisories are [GHSA-82x6-q7mm-w9cf](https://github.com/advisories/GHSA-82x6-q7mm-w9cf) and [GHSA-v5mp-jgw5-2x6j](https://github.com/advisories/GHSA-v5mp-jgw5-2x6j). No web source imports Anchor. This does not remove or change the separately maintained Anchor contract workspace.

| `bigint-buffer@1.1.5` — **high**, [GHSA-3gc7-fjrx-p6mg / CVE-2025-3194](https://github.com/advisories/GHSA-3gc7-fjrx-p6mg)                                                                                          | Web/SDK → `@solana/spl-token` → `@solana/buffer-layout-utils`. SPL checks minimum account sizes and slices the fixed mint/account layout; the numeric decoder passes fixed 8-byte `u64` fields to `toBigIntLE`. Devnet additionally requires exact 82/165-byte account sizes. No direct application call accepts arbitrary buffers. The native converter can load on Node; a local pure-JS fallback warning is **not** a deployment guarantee. | No patched release is listed. Preserve the fixed-size decoding boundary and investigate an upstream SPL migration or reviewed replacement using native `BigInt` buffer readers. Test mint/account decoding, Token-2022, and malformed lengths before replacing anything. Retain as an unresolved production dependency risk. |

No dependency overrides or exploit payloads were applied during this review. Repeat the trace after lockfile updates, preserve these unresolved items in release tracking, and run production audit plus web build and native/Expo export checks before declaring them remediated.
