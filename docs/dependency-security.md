# Dependency security review

Reviewed 13 September 2026 using the committed lockfile and **pnpm 10.31.0**. The production audit fell from **57 findings (1 critical, 31 high, 25 moderate)** to **8 findings (0 critical, 3 high, 5 moderate)**. These are package/version findings, not a count of demonstrated application exploits. The remaining eight findings span six advisories across five packages. This is not a clean audit or a complete deployment security assessment.

### Expo archive compatibility

Forcing tar 7 alone breaks Expo CLI 0.22.28: its compiled default-import helper sees tar's `__esModule` marker but tar exposes no default export, leaving `default.extract` undefined. `patches/@expo__cli@0.22.28.patch` changes exactly two import wrappers to hold the CommonJS module explicitly. The patch is version-bound, recorded with a hash in `pnpm-lock.yaml`, and applied by pnpm on clean installation.

The existing file extraction and template stream APIs remain unchanged. Installed cacache 18.0.4 declares tar but has no tar call in its runtime `lib` sources; its cache write/read/verification API was also exercised. Remove or update the patch when upgrading Expo CLI, after confirming its imports support tar 7. The source maps included by upstream still describe its original imports.

## Residual findings

| Package                      | Remaining issue and observed exposure                                                                                                                                                                                                                                                                                                                                                                                  | Required follow-up                                                                                                                                                                                                |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bigint-buffer@1.1.5`        | One high [buffer-overflow advisory](https://github.com/advisories/GHSA-3gc7-fjrx-p6mg), with no patched release reported. It is reached through SPL Token's buffer layout utilities. This installation falls back to JavaScript because the native addon is absent; another deployment can load the native addon. Current integer layouts use fixed-width buffers, which does not prove every downstream path is safe. | Replace or patch the upstream native conversion dependency with reviewed bounds checks; verify the actual deployment artifact and addon policy. Do not treat a local fallback warning as a production mitigation. |
| `image-size@1.2.1`           | Two high advisories for malformed ICNS, JXL and HEIF image parsing. No patched version is reported in the audit. The observed path is Metro's build/asset tooling; malformed repository assets can hang a build. [Original researcher disclosure](https://joshua.hu/image-size-infinite-loop-dos-vulnerabilities).                                                                                                     | Use reviewed assets and isolated build workers; adopt an upstream patch or maintained replacement. Do not expose Metro as a production API or feed untrusted images into its asset pipeline.                      |
| `uuid@7/8/9`                 | Three moderate version findings for one [v3/v5/v6 output-buffer advisory](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq). Inspected jayson, xcode and MetaMask utility callers use `v4()` without output buffers, outside that specific trigger.                                                                                                                                              | Upgrade the parent packages on a tested migration; no forced multi-major UUID override was applied. Reassess if callers change.                                                                                   |
| `decode-uri-component@0.2.2` | One moderate [malformed percent-decoding denial-of-service advisory](https://github.com/SamVerschueren/decode-uri-component/security/advisories/GHSA-vcc3-ghjq-m6fr) through WalletConnect's query-string dependency. The fixed 0.5.0 release is ESM and cannot safely replace the older CommonJS function API blindly. Wallet URL/query inputs remain a relevant boundary.                                            | Upgrade the parent query-string/WalletConnect chain with browser-wallet validation or apply a reviewed compatible backport.                                                                                       |
| `stream-json@1.9.1`          | One moderate [deeply nested path-filter advisory](https://github.com/uhop/stream-json/security/advisories/GHSA-528h-pc64-c93x) through jayson. Inspected jayson imports `StreamValues` and `Verifier`, not the vulnerable path filters. The fixed 3.x API is a major migration.                                                                                                                                        | Update jayson/Solana dependencies through their supported versions; avoid adding unbounded path-filter processing meanwhile.                                                                                      |

The scoped install retains pre-existing peer warnings for optional `utf-8-validate`, Farcaster's TypeScript range and a Privy transitive Solana sysvars range. Those require parent dependency alignment, not arbitrary peer overrides. No advisory was suppressed.

## Reproduce

```sh
npm exec --yes --package=pnpm@10.31.0 -- pnpm install --frozen-lockfile --ignore-scripts
node --test scripts/test-dependency-compatibility.cjs
npm exec --yes --package=pnpm@10.31.0 -- pnpm audit --prod
```

The two compatibility tests pass for actual Expo template extraction, its forced JavaScript extraction fallback, plist round-trip serialization and cacache put/get/verify. Production Next builds and Expo exports remain necessary after these dependency changes; passing this smoke test alone does not validate every wallet or native-device flow. Re-run the audit at deployment time because advisory data changes. Keep the repo's package-manager pin: pnpm 11 does not read these `package.json` override settings.
